# Team website: WIUT Hackathon 2026, CV track

Static React site (Vite + TypeScript + Tailwind). Every page except the upload in the live demo is served from
static files, so the site keeps working even if the demo server is down.

## Run

```bash
npm install
cp .env.example .env      # demo backend: our Hugging Face Space by default
npm run dev               # http://localhost:5173
npm run build             # static output in dist/
```

Deploy `dist/` to any static host (Vercel, Netlify, GitHub Pages). Routing uses URL hashes (`/#/results`),
so no rewrite rules are needed. Set the `VITE_*` variables in the host's build settings.

| Variable | Meaning |
|---|---|
| `VITE_GRADIO_SPACE` | Hugging Face Space of the demo (default `Roicaluste/wiut-traffic-events`). |
| `VITE_API_BASE` | REST demo server instead of the Space. Both empty = mock mode (synthetic results, clearly labelled). |
| `VITE_MAX_UPLOAD_MB` | Upload size limit shown and enforced in the browser (default 2000). |
| `VITE_MAX_DURATION_SEC` | Clip length limit (default 150). |

## Pages

| Route | Rubric section | Data |
|---|---|---|
| `/` | Overview | `content.json`, `predictions_samples.json` |
| `/demo` | Live demo | Demo API; "Show a sample result" uses static data |
| `/results`, `/results/:video` | Results on the sample videos | `predictions_samples.json`, `samples.json` |
| `/eda` | EDA | `eda.json`, `samples.json` |
| `/approach` | Problem and approach | `content.json` → `approach` |
| `/report` | Report | `content.json` → `report`, `dev_scores`, `ablations` |
| `/team` | Team | `team.json` |
| `/links` | Links | `content.json` → `links` |

`/results/:video?t=42` opens a video at 42 s. The result view (player, event timeline, risk curve, event table,
all synced) is the same component in Results and in the demo.

## Where the data comes from

Everything in `public/data/` and `public/media/` about the sample videos is generated by the repository
(https://github.com/Roicalus/wiut-traffic-events), not written by hand:

```bash
# in the repository
python tools/dev_loop.py --videos samples                  # Part A cache (tracks, light, zones)
python tools/visualize_debug.py --video samples/C3896.MP4 --predictions predictions_samples.json   # per video
python tools/export_site.py --site ../site                 # data/*.json + media/
```

`predictions_samples.json` is the submission file unchanged. Hand-written text lives in
`public/data/content.json` (approach, report, ablations, links) and `public/data/team.json`; the EDA findings
come from `docs/eda_findings.json` in the repository.

Videos must be H.264 MP4 with faststart (the export script encodes them this way).

## Live demo backend

By default the demo page talks to our Hugging Face Space (`VITE_GRADIO_SPACE`, the repository's
`demo/app.py`) through `@gradio/client`: upload, progress per stage from the Gradio queue, then the result's
`events.json` and annotated video. Requests to `*.hf.space` are sent without cookies, because the Space
answers CORS preflights without `Access-Control-Allow-Credentials`. The Space runs the detector on ZeroGPU
when a GPU is free and on its CPU otherwise (anonymous visitors usually get the CPU path: about 17 s for a
20-second 1080p clip).

A REST server with the contract below also works: set `VITE_GRADIO_SPACE=` (empty) and `VITE_API_BASE`.

| Endpoint | Response |
|---|---|
| `GET /health` | `200 {"ok": true}` |
| `POST /jobs` (multipart, field `file`) | `{"job_id": "..."}`, or 4xx `{"detail": "readable message"}` |
| `GET /jobs/{id}` | `{"status": "queued"\|"running"\|"done"\|"error", "progress": 0..1, "stage": "...", "error": null}` |
| `GET /jobs/{id}/result` | `{"video": {"duration": s, "fps", "width", "height"}, "events": [[s, e, label]], "risk": [[t, score]], "annotated_video_url": url or null}` |
